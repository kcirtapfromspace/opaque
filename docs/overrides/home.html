Publish a GitHub Actions secret.

One operation. A policy requiring approval for every write.

  1. 01

    Request the operation.

    The agent names a repository, secret, and stored reference.

    Example command 
    opaque github set-secret \
  --repo myorg/api \
  --secret-name DEPLOY_KEY \
  --value-ref keychain:opaque/deploy-key
  2. 02

    Review before the write.

    Opaque checks policy. You review the request before approving.

    Repository
    myorg/api
    Secret name
    DEPLOY_KEY
    Operation
    github.set_actions_secret
  3. 03

    Inspect the outcome.

    Opaque calls GitHub and records the observed result. The response omits the secret value.

    Inspect your run
    opaque audit tail --limit 10
opaque audit verify

Know the boundary.

A separate broker identity isolates custody from the agent's OS user. The default same-user setup does not. Other agent access remains outside Opaque.

Audit records describe observations. They do not prove every external effect; an interrupted call can leave the outcome unknown.
